# Индекс проблем: Hermes, OpenClaw, VPS и наши устройства

Документированные проблемы, с которыми мы столкнулись с начала работы агентской системы (апрель–сентябрь 2026 года). Это только перечень; отдельные разборы и способы решения будут добавлены позже. Повторения одного и того же сбоя объединены.

## VPS и работа агентов

- **P-001.** Две установки OpenClaw с разными версиями CLI и рабочего gateway.
- **P-002.** Одновременный запуск системного и пользовательского OpenClaw gateway с циклом перезапусков.
- **P-003.** Обновление OpenClaw ставилось не в каталог, из которого запускался рабочий сервис.
- **P-004.** Новая версия OpenClaw требовала более свежий Node.js, чем использовал плановый обновитель.
- **P-005.** Обновления OpenClaw перезаписывали локальные настройки и совместимые патчи.
- **P-006.** OpenClaw Desktop и VPS gateway оказывались на несовместимых версиях.
- **P-007.** Hermes gateway числился активным, но переставал отвечать в Telegram после зависшего завершения задачи.
- **P-008.** Hermes CLI выдавал правильный ответ, затем завершался с кодом 134 при очистке ресурсов.
- **P-009.** Сервисы Hermes и OpenClaw исчерпывали лимит открытых файлов; SQLite переставал открывать базу.
- **P-010.** Временные сборки, кэши, сессии и резервные копии заполняли диск VPS.
- **P-011.** HAProxy конфликтовал с Telegram MTProto proxy за один порт.
- **P-012.** Cloudflare Access блокировал проверку Let's Encrypt при продлении сертификатов.
- **P-013.** Наблюдатели и проверки здоровья выдавали ложные предупреждения или не замечали настоящие сбои.
- **P-014.** Самоперезапуск агента прерывал его текущую задачу.

## Авторизация, модели и резервные маршруты

- **P-015.** Hermes и OpenClaw сталкивались с конфликтом за Codex OAuth refresh token.
- **P-016.** Hermes получал `refresh_token_reused`, `relogin_required` и истёкший токен для основной модели.
- **P-017.** Повторные попытки авторизации Codex через device code упирались в ограничения и тайм-ауты.
- **P-018.** После обновлений OpenClaw выбирал устаревший или неверный путь к модели Codex.
- **P-019.** OpenClaw попадал в цикл `Blocked hostname` после cooldown авторизации.
- **P-020.** Резервные модели возвращали ошибки авторизации, лимита запросов или оплаты.
- **P-021.** Проверка `hermes doctor` сообщала о сбое Gemini, хотя реальный запрос к модели работал.
- **P-022.** Прямой доступ VPS к Google/Gemini ограничивался регионом или сетью.
- **P-023.** Локальный Google proxy блокировался защитой от запросов к приватным адресам.
- **P-024.** Устаревший прокси-узел Google AI переставал принимать соединения.
- **P-025.** Резервный маршрут Gemini/NotebookLM зависел от одного внешнего узла и терял доступ при его отказе.

## MCP, внешние сервисы и безопасность

- **P-026.** Некорректные схемы инструментов Notion MCP мешали запуску Hermes gateway.
- **P-027.** Проверка некоторых Notion и Supabase MCP инструментов возвращала HTTP 403.
- **P-028.** Ошибка вложенной ссылки на переменную окружения ломала авторизацию Notion MCP.
- **P-029.** Google Workspace MCP нестабильно запускался после перезагрузки.
- **P-030.** Первое ограничение Google Workspace MCP адресом localhost остановило сервис.
- **P-031.** Работа с двумя Google-аккаунтами через Workspace MCP путалась с первоначальным планом авторизации.
- **P-032.** Доступ к Cloudflare и Netlify для публикации оказывался неполным из-за токенов и настроек.
- **P-033.** Отдельный профиль Hermes Sherlock не имел собственной авторизации Canva MCP.
- **P-034.** Публичный MCP gateway первоначально открывал слишком широкие административные инструменты.
- **P-035.** Секреты обнаруживались в конфигурации или параметрах запуска сервисов.
- **P-036.** Проверки безопасности и реальные настройки внешнего доступа расходились.
- **P-037.** Отправка файлов Hermes на iMac через SSH давала ошибки синхронизации и скрывала первичную причину.

## Взаимодействие агентов и Telegram

- **P-038.** Передача задачи Hermes → OpenClaw ломалась из-за устаревшего режима запуска.
- **P-039.** Результат OpenClaw записывался не в тот каталог или неверно разбирался из JSON.
- **P-040.** Systemd watcher находил не ту версию OpenClaw из-за PATH.
- **P-041.** Передача между агентами могла зависать, дублироваться или терять подтверждение результата.
- **P-042.** Агент сообщал о выполнении действия без проверяемого результата.
- **P-043.** OpenClaw иногда молчал в Telegram-группе вместо ответа пользователю.
- **P-044.** Telegram на macOS показывал «сообщение не поддерживается» для обычных ответов OpenClaw.
- **P-045.** Карточки прогресса инструментов OpenClaw снова вызывали «сообщение не поддерживается».
- **P-046.** В Telegram-топике сохранялось устаревшее состояние сообщения или инструмента.
- **P-047.** Совместимость форматирования Telegram требовала отдельных исправлений для Hermes и OpenClaw.
- **P-048.** Дайджест Seeker не запускался через системный Python без нужного модуля.
- **P-049.** Задачи в watcher попадали в обработку вместе со служебными файлами.

## iMac и настольные приложения

- **P-050.** Официальная сборка Hermes Desktop для Apple Silicon не запускалась на Intel iMac.
- **P-051.** Hermes Desktop терял связь с исправным VPS backend из-за зависшего SSH-туннеля.
- **P-052.** Hermes Desktop показывал ошибку авторизации, вызванную истёкшим OAuth-токеном на VPS.
- **P-053.** Обновление Hermes Desktop срывалось из-за прав на каталог npm cache.
- **P-054.** OpenClaw Desktop повторял запрос Approve Mac для уже подключённого iMac.
- **P-055.** Обратный SSH-туннель iMac → VPS обрывался или попадал под блокировку при частых переподключениях.
- **P-056.** Локальный sing-box на iMac не запускался, хотя прокси был прописан.
- **P-057.** Устаревший узел подписки переставал разрешаться через DNS или принимать TCP.
- **P-058.** PAC-файл существовал, но системная настройка прокси Wi-Fi была выключена.
- **P-059.** PAC с `file://` не принимался браузером; локальный PAC-сервер добавлял отдельную точку отказа.
- **P-060.** Доступ к Gemini и NotebookLM пропадал из-за регионального определения IP.
- **P-061.** DNS на iMac зависал при сочетании AmneziaVPN и локального прокси.
- **P-062.** Правило для российских сайтов направляло кабинет хостера в неработающий маршрут.
- **P-063.** Требование выводить все `.ru` сайты через обычного провайдера устройства не выполнялось серверной маршрутизацией.
- **P-064.** Длинные чаты Codex на iMac зависали при сжатии контекста или обрыве удалённого потока.

## VPN и устройства

- **P-065.** Миграция AmneziaWG 2 → 3 ломалась на несовместимых параметрах конфигурации.
- **P-066.** VPN показывал handshake, но реальный трафик устройства не проходил.
- **P-067.** Версию AmneziaWG ошибочно определяли по имени контейнера.
- **P-068.** Сосуществование старого и нового VPN-контейнеров путало активные профили устройств.
- **P-069.** После миграции отдельные устройства требовали восстановления peer и повторной проверки трафика.
- **P-070.** Прямой выход через немецкий VPS не открывал NotebookLM из-за регионального отказа Google.
- **P-071.** Работа Google AI на телефонах зависела от доступности отдельного прокси-выхода.

## Lenovo, память и рабочий процесс

- **P-072.** Kaspersky перехватывал HTTPS и мешал авторизации Grok Bot на Lenovo.
- **P-073.** Доступность Hermes backend не означала, что Windows Hermes Desktop обновлён и работает.
- **P-074.** Работающий OpenClaw gateway не доказывал наличие доступного Windows-клиента или панели.
- **P-075.** Документы Brain и фактические версии, маршруты или возможности агентов расходились.
- **P-076.** Зеркала Brain в Google Drive создавали дубликаты и устаревшие ссылки.
- **P-077.** Большие или неправильно оформленные файлы skills хуже обнаруживались и переносились между агентами.
- **P-078.** Память Honcho смешивала постоянные сведения о пользователе с временными задачами и чужими материалами.
